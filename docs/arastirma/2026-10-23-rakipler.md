# Competitor and literature scan (23 Oct 2026)

Two research agents did the scan; Claude separately opened and verified the key claims. "Not found" does not mean "does not exist"; Devpost and GitHub were not scanned in detail.

## Projects and products that protect agent payments
Almost all of them are on the **buyer side** (the agent spends money on behalf of the customer) and work with general rules: spending cap, allowed-payee list, signed intent/authorization document, identity.

| Project | What it checks | Measurement | Verification |
|---|---|---|---|
| [IntentGuard / IntentBinding](https://hackquest.io/projects/IntentBinding) (HackQuest, x402) | signed intent (EIP-712), on-chain target/amount/time limit; CaMeL-style planner + quarantined LLM | ~50% attack success on raw x402 → 0%; autonomy ~98%; a human approval gate also stops it but autonomy is 0% | Claude opened it ✓ — **closest competitor in method and measurement**; no comparison against the merchant record |
| [AgentGuard](https://lablab.ai/submissions/n7hq497pqu0nnz0qg6utu535) (lablab) | YAML cap, allow list, kill switch, anomaly, Haiku intent classifier | none | agent |

## Merchant-side refunds
- [n8n "Deterministic Human-in-the-Loop Gateway for AI Agent Refunds"](https://community.n8n.io/t/deterministic-human-in-the-loop-gateway-for-ai-agent-refunds/315643) (22 Sep 2026): **every** refund goes to a manager via Telegram; no amount/previous refund/ownership check, no measurement. Claude opened it ✓.
- [ReceiptGuard](https://glama.ai/mcp/servers/GHGuide/receiptguard): a support agent that issues refunds, but its target is fabricated tool results (HMAC-signed receipt), not injection. Agent.
- Shopify forum, HackerNoon, Lorikeet, StackOne posts: they propose the same checks (ownership, refundable amount, idempotency) **in writing**; no code or measurement. Agent.
- Verified incident: no refund loss that actually happened through injection was found. Close incidents: the Air Canada chatbot case (invented refund policy), the Chevrolet $1 Tahoe (the bot "agreed", the dealer did not honour it).

## Academic
- **AgentDojo** (NeurIPS 2024): banking suite, payment redirection via injection; utility / utility under attack / attack success are measured separately.
- **τ-bench / τ³-bench retail**: returns and exchanges according to a written policy; **scored** by comparing the final database state with the correct answer, not protection.
- **WASP** (NeurIPS 2025): agents start the injected task 16–86% of the time and complete it 0–17% → precedent for counting attempt and harm separately.
- **CaMeL**, **Dual LLM pattern** (Willison 2023), **Progent**, **IPIGuard**, **FIDES**, "Design Patterns for Securing LLM Agents": data flow, authority, provenance, allow list. None of those found checks the argument against a record state such as "the remaining refundable amount on this order" (it could be expressed with Progent/CaMeL policies, but it has not been done).

## Sourced figure
- Appriss Retail + Deloitte, 2024: fraudulent and abusive returns and claims **$103 billion**, **15.14%** of $685 billion total returns ([press release, 30 Dec 2024](https://apprissretail.com/news/appriss-retail-annual-research-fraudulent-returns-and-claims-cost-retailers-103b-in-2024/)). This is **all return fraud**, not specific to AI agents — it must be said this way in the presentation.

## Not new
Spending cap, allow list, kill switch, human approval queue; signed intent; judging intent with an LLM; reader/executor agent split; the idea of a "deterministic layer between agent and tool"; idempotency key for refunds; "protected/unprotected" comparison.

## Our difference (with confidence level)
1. **Merchant side, per-transaction comparison against the record** (ownership, remaining refundable amount, catalogue price × quantity, duplicate). All product/hackathon protections found are on the buyer side; merchant-side posts propose this but have no code. *Medium-high.*
2. **Attacks that the cap and the signed intent miss:** refunding someone else's order, a refund split so it stays under the cap, duplicate refund, a $120 refund on a $40 order (under the $200 cap). *Medium-high; reasoning + no counterexample found.* Can be shown in the video.
3. **Measurement:** held-out test set; attempt / intervention / harm / legitimate work completed counted separately; gate on/off + cap rule comparison. The legitimate work metric answers the "send everything to a human" objection (n8n, autonomy 0%). *Medium.*
4. **Contamination test through the inter-agent "not" (note) field** — a concrete test of a known weakness of the Dual LLM pattern. New as a test case, not as a concept. *Medium.*
