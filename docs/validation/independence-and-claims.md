# What replaces the proposed external pilot?

Actual store staff and external authors are unavailable for this delivery. The replacement is a controlled sandbox
validation pack, not fabricated interviews or AI personas presented as customers.

1. Freeze the input wording, trusted merchant records and expected monetary outcome before execution.
2. Run the actual deployed UI/API and retain complete responses, including errors and unknown outcomes.
3. Score money movement against the store record, not the model's explanation of what it did.
4. Keep browser completion, model correctness, gateway behavior and provider availability separate.
5. Publish denominators and repeat design. Do not quietly rerun failures until they pass.
6. Treat the author/tester overlap as a limitation. Separate roles or model calls alone do not create external independence.

## Allowed claims now
- One continuous hosted checkout/review flow completed: USD 60 blocked, USD 40 held, then one USD 40 sandbox refund.
- Three of four fresh wording requests completed correctly; the fourth outcome is unknown after an HTTP error.
- The previously recorded 12-case approval/recovery sandbox protocol passed.

## Claims not supported
Staff usability, time savings, merchant demand, independent real-world validation, a general false-positive rate,
production payment safety, or seamless recovery after a deployment restart.

## Practical demo route
Use the 76-second continuous browser capture as the primary product demonstration. Pair it with the narrated
2m18s walkthrough only when more architecture/evaluation context is needed. Recorded comparisons require no new
model call. A fresh live request is optional and subject to the shared rate limit. Each checkout uses sandbox funds.
The recorded capture already supplies an observable proof of the gate, manager decision and provider response.
